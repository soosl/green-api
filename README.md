# GREEN-API Messenger Client

Веб-клиент для обмена сообщениями через GREEN-API с поддержкой Telegram и WhatsApp.

**Демо:** [https://green-api-vert.vercel.app/](https://green-api-vert.vercel.app/)

## Возможности

- подключение Telegram- и WhatsApp-инстансов GREEN-API;
- проверка состояния и авторизации инстанса;
- проверка существования аккаунта получателя;
- создание чата по номеру телефона;
- отправка и получение текстовых сообщений;
- получение событий через long polling;
- оптимистичное отображение отправленных сообщений;
- повторная отправка сообщений при ошибке;
- отображение статусов сообщений:
  - отправляется;
  - отправлено;
  - доставлено;
  - прочитано;
  - ошибка;
- защита от дублирования входящих сообщений;
- восстановление активного чата после перезагрузки страницы;
- хранение данных в пределах текущей вкладки;
- адаптивный интерфейс.

## Поддерживаемые мессенджеры

- Telegram
- WhatsApp

Архитектура приложения позволяет добавить новый мессенджер без существенного изменения компонентов интерфейса.

### `api`

Содержит HTTP-клиент GREEN-API. Он отвечает за формирование запросов, обработку ответов и преобразование ошибок API.

### `messengers`

Содержит конфигурацию поддерживаемых мессенджеров:

- тип инстанса;
- подписи элементов интерфейса;
- правила проверки получателя;
- ограничения длины сообщения;
- преобразование номера телефона в идентификатор чата.

Компоненты интерфейса работают с единым контрактом и не зависят от особенностей конкретного мессенджера.

### `hooks`

Хук `useChatMessages` управляет:

- отправкой сообщений;
- оптимистичным обновлением интерфейса;
- повторной отправкой;
- получением уведомлений;
- обработкой входящих сообщений;
- обновлением статусов доставки;
- предотвращением дубликатов;
- сохранением истории активного чата.

### `storage`

Данные подключения, выбранный чат и сообщения сохраняются в `sessionStorage`.

Данные существуют только в пределах текущей вкладки браузера и удаляются после её закрытия. При ручном отключении от инстанса сохранённая сессия также очищается.

## Локальный запуск

### Требования

- Node.js 20 или новее;
- npm;
- настроенный и авторизованный инстанс GREEN-API.

### Установка

Клонируйте репозиторий и установите зависимости:

```bash
npm install
```

Запустите приложение в режиме разработки:

```bash
npm run dev
```

После запуска приложение будет доступно по адресу:

```text
http://localhost:5173
```

## Подключение к GREEN-API

Для подключения понадобятся параметры из личного кабинета GREEN-API:

- `apiUrl`;
- `idInstance`;
- `apiTokenInstance`;
- тип мессенджера.

Пример адреса API:

```text
https://4100.api.green-api.com
```

Перед подключением инстанс должен быть авторизован и находиться в состоянии `authorized`.

Параметры вводятся непосредственно в интерфейсе приложения. Создавать файл `.env` не требуется.

> Не передавайте данные своего инстанса третьим лицам и не добавляйте их в репозиторий.

## Настройка уведомлений

Чтобы приложение получало входящие сообщения и обновляло статусы доставки, в настройках инстанса GREEN-API должны быть включены webhook-уведомления.

Пример необходимых настроек:

```text
Отмечать входящие сообщения прочитанными
Получать уведомления о входящих сообщениях и файлах
Получать уведомления о сообщениях, отправленных с телефона
Получать уведомления о сообщениях, отправленных с API
Получать уведомления о статусах отправленных сообщений
```

Приложение получает события методом `receiveNotification`, обрабатывает их и удаляет из очереди методом `deleteNotification`.

Если уведомления отключены, отправка сообщений может продолжать работать, но входящие сообщения и изменения статусов отображаться не будут.

## Статусы сообщений

В приложении используется единая модель статусов:

```text
sending → sent → delivered → read
              ↘ failed
```

События GREEN-API преобразуются во внутренние статусы, не зависящие от выбранного мессенджера.

Приложение также учитывает события, пришедшие не по порядку: более поздний статус не заменяется более ранним.

## Добавление нового мессенджера

Для подключения нового мессенджера необходимо:

1. Добавить его идентификатор в тип `MessengerId`.
2. Добавить конфигурацию в `MESSENGERS`.
3. Реализовать проверку получателя.
4. Реализовать преобразование номера в идентификатор чата.
5. При необходимости дополнить обработку webhook-событий.

Формы авторизации, создания чата и основное представление переписывать не потребуется.

## Ограничения

- поддерживаются только текстовые сообщения;
- одновременно отображается один активный чат;
- история хранится только в текущей вкладке браузера;
- серверная часть отсутствует;
- запросы к GREEN-API выполняются непосредственно из браузера;
- для получения сообщений и статусов необходимы правильно настроенные webhook-уведомления;
- автоматические тесты в рамках тестового задания не добавлялись.
